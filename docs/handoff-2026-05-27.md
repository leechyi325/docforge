# DocForge 交接总结

日期：2026-05-27

## 当前状态

DocForge 当前是一个桌面端文档格式整理 MVP，核心能力是本地确定性格式整理，模型只作为可选的格式指令解析辅助。截至 `d11fdf1` 的代码基线已经推送到 `origin/main`。

近期关键提交：

- `71b36e2 feat: add docx formatting and model providers`
- `d11fdf1 fix: harden desktop document processing`

当前推荐处理链路：

```text
Markdown 或 .docx 输入
  -> engine.cli format
  -> engine.pipeline.format_document
  -> python-docx 本地确定性格式整理
  -> 格式诊断
  -> CLI 或桌面端消费 JSON 结果
```

`generate` 仍保留给 Markdown 旧链路兼容使用。后续新增功能和通用入口优先使用 `format`。

## 已交付能力

- Markdown 输入仍通过 Pandoc 转换为 `.docx` 后整理。
- 已支持直接输入 `.docx` 并输出新的 `.docx`。
- `.doc` 老格式会被明确拒绝。
- 当前 profile 包括 `general`、`official`、`meeting_minutes`、`briefing`、`speech`。
- 临时自然语言格式指令可通过本地规则或远程模型解析。
- 当前 provider 包括 `local`、`openai`/`openai-responses`、`openai-compatible`、`anthropic-messages`。
- 模型输出必须解析为 JSON，并通过本地类型模型校验后才能进入格式整理。
- 桌面端会把 provider、模型名、Base URL 等参数传给 Python CLI，API Key 通过环境变量传给子进程，不进入 CLI argv。
- Tauri 调 Python 时优先使用 `DOCFORGE_PYTHON`，其次自动找仓库 `.venv/bin/python`，最后回退系统 Python。
- 桌面端现在会展示处理失败原因，不会一直卡在“正在转换并整理 docx”。
- Tauri 编译所需的 `Cargo.lock`、`build.rs`、`icons/icon.png` 已补齐。

## 重要边界

Python 引擎仍是业务源头。React 和 Rust 只做参数收集、CLI 调用和状态展示，不应重新实现格式整理、诊断、模型 provider 或修复逻辑。

远程模型 provider 可以解析格式指令，未来也可以辅助结构识别或诊断建议。除非后续明确扩大范围，否则模型不能直接编辑 `.docx`、生成最终 Word 文件、执行本地命令或改写正文内容。

所有真正落地的格式动作都必须经过本地类型数据和确定性代码。修复动作仍必须走 `FixAction` 以及 `engine/fixer/apply_fixes.py` 中的白名单。

## 运行方式

Python 环境：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
```

CLI 示例：

```bash
.venv/bin/python -m engine.cli format \
  --input input.docx \
  --profile general \
  --format-instruction "标题居中，正文仿宋三号" \
  --llm-provider local \
  --output output.docx
```

桌面端开发启动：

```bash
cd apps/desktop
npm install
export DOCFORGE_PYTHON="$(pwd)/../../.venv/bin/python"
npm run tauri dev
```

`npm run dev` 只启动 Vite/browser UI，不能调用 Rust/Python 后端。它只适合 UI-only 检查，不适合测试文档处理。

## 已知限制

- 不支持 `.doc` 老格式。
- 不支持在线 Word 级预览。
- 不支持 Word/WPS 插件。
- 不支持正文润色、扩写或改写。
- 直接整理 `.docx` 时，输出路径必须和输入路径不同。
- 表格、页眉、页脚、批注、脚注、修订痕迹等复杂 Word 区域还不是一等格式整理对象。
- OpenAI-compatible provider 对 JSON Schema 的支持差异较大；当前 adapter 会按 JSON Schema、JSON object、纯 JSON 文本逐级回退，但返回结果仍必须通过本地校验。
